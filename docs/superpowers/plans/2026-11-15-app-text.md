# App text in the database Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Store the app's own words in `public.app_text` with draft, publish and roll back, edit them at `/admin/app-text`, and read the published text on phones with the code default as the safety net.

**Architecture:** One migration (table, select policy, `security definer` write functions, a private publish function #289 extends). One JSON file is the single source of the defaults; the code and the seed script both read it. A server reader caches all published rows for 60 seconds; pages pass the texts to client screens through a context whose hook falls back to the default.

**Tech Stack:** Next.js 16 App Router (cacheComponents), React 19, TypeScript, Supabase (`@supabase/supabase-js`, `@supabase/ssr`), Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-15-app-text-design.md`

## Global Constraints
- No service-role key anywhere; writes go through functions that check `public.is_content_editor()`.
- Key format `^ui\.[A-Z][A-Z0-9-]*\.[a-z][a-z0-9_]*(\.[a-z][a-z0-9_]*)*$`; 13 keys exactly as in the spec table, defaults byte-equal to today's strings (`Let’s` uses U+2019).
- Cache at most 60 000 ms; a failed read is not cached and answers the defaults.
- `DESIGN.md` tokens only; no sideways scroll at 360 px (and 320 px at 200% text).
- Migration named after `20261116000000`: `20261117000000_app_text.sql`.
- English only. Commits `feat: … (#288)` ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus
- A blank or whitespace-only draft: refused by the action and the database (screens never blank). Test in Task 1 (SQL check) and Task 5 (action).
- A publish racing a cache read: a read in flight when `clear()` runs must not overwrite the cleared cache. Test in Task 3.
- A row with an unknown key or a key removed from the catalog: ignored by reader and admin rows. Tests in Tasks 3 and 5.
- Re-running the seed after a writer published an edit: must not overwrite it. Test in Task 2 (SQL text) and in the stub.
- Roll back to a version newer than or equal to the published one, or never published: refused. Test in Task 1 (SQL text) and Task 5 (admin rows only offer earlier published versions).
