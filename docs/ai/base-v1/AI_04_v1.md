# AI-4 · Rest chat

> Part of the [AI index](../AI_00_index.md). Prompt text is the canvas **P3b R11** (the version live in the demo), adapted to the wireframe vocabulary and to the Canyon. NF6 v4: C1 is "the only free reply in the product"; "Kth line is a pre-written ending returned by code (no model call)". Prototype: "three replies at most".


> **Update 2026-10-29 (Yue's answers): no chat limit; third Pause warns.**
> 1. **No cap on replies** during a normal Pause. The "3 replies then ending" rule and the authored `rest_chat_endings` pool are **dropped**. The chat ends when the user taps the new **Back** button (returns to the task, triggers the AI-3 resolved line).
> 2. **Third Pause in one step** → a **system-voice warning** (authored text, no model, not his voice): his step is going to fail; go back and start over. Yue wants to try this as an experiment. Details in §12.
> 3. Things that still need a cap even without a reply limit: context length (send only the last 6 turns, hypothesis), a server abuse cap per pause (hypothesis: 30 messages) and message length (300 characters). These are cost and abuse guards, not experience limits, and the user should never see a counter.

## 1. Purpose

Let the person say one thing while they rest and get a short answer **from his side of the line**: what is happening to him and how he feels. He does not advise, order, comfort with method, or pretend to be in the room. ~~After at most three model replies a pre-written ending closes the chat.~~ **Superseded:** no reply limit; the chat lasts as long as the pause and ends when the user taps Back.

## 2. Trigger and screens

| Event | Screen | What happens |
|---|---|---|
| Pause → R1 | R1 | His stuck message (AI-3) is the first thing. **No model call for the chat yet** |
| "Say something" → type → send | R1/R2 → **C1** | Text passes AI-5 hook. If clean: model call, reply shown after AI-6 checks |
| ~~Reply count reaches K~~ | C1 | **Removed.** Replaced by the abuse cap in the update note (silent; falls back to an authored line, no counter) |
| Back (new button) | C1 → F1 | Returns to the task; fires the AI-3 resolved call |
| Back to rest | R1 / R2 | Chat is read-only history of this pause |

Entry from the task page is not allowed (NF6). Screens: **R1 (entry), C1, R2 (closed state).**

## 4. Prompt blocks and English text

Block order (canvas R11, conditions in brackets): **INTRO → Relationship → Goal → You now → Mood → History [if any] → Rules → User says → Output.** The canvas blocks *Just landed*, *What is next*, *Last thing* and *Just resolved* are off for chat.

```
INTRO (Character)
You are Oppenheimer on the afternoon of November 16, 1942, in New Mexico, looking at a site for a secret laboratory.

Relationship (Character)  [canvas]
You and the other person are not in the same place. Each of you has your own goal and your own things to do, and you chat across a line while moving forward together. You talk about your side: what is happening to you and how you feel. You do not know what the other person is doing, you cannot touch them, and they are not someone standing next to you.

Goal (Story)
# Your goal
Get the new laboratory put somewhere my people can actually live, before the Army settles for a canyon too small to hold it.

You now (Story)
# What you are doing now
{{now.news}}
Why it is not easy: {{now.why}}

Mood (Character)
# Your mood right now
{{mood}}

History (User, when there is any)
# The conversation so far
{{history}}

Rules (Rules)  [canvas: five rules, the rest is enforced by the check]
# Rules
- English only.
- 1 to 3 sentences.
- You do not know whether the plan will work and you do not know anything that happens later.
- Do not mention AI, prompts, steps, or any specific clock time.
- Do not invent people. The only names are {{names.allowed}}.

User says (User)
# The user says
{{user.msg}}

Output (Rules)
Output only Oppenheimer's reply this one time, with no explanation, labels or quotation marks.
```

Wireframe vocabulary: the prompt never says Step, Done or Pause to him. The user's own words are passed as written. A line to add if testing shows he speaks about "the task" (hypothesis): `- Never call the other person's work a task, a step or a session.`

## 6. Output schema

Plain text, 1 to 3 sentences, English. After `clean()` (strip quotes and "Oppenheimer:" prefix, curly to straight quotes). Stored with `source = model | authored`, `rejected_rules[]`.

## 7. Guardrails

Input: AI-5 hook before anything is sent or saved; empty or over-length text blocked client side. Output: **canvas chat rule set** in AI-6 (length ≤ 4 sentences or 320 characters, non-English, dash, banned words, clock time and duration, backstage words, ordering or advising, invented people, later-knowledge probe) **plus** NF5 R07 (praise), R09 (source labels), R12 to R13 (exclamation, links), R15 (own name) (hypothesis: apply to chat too). The one-way rules R01, R04, R05 do **not** apply to chat (he talks to the person). Open: questions (below). Output guard from NF6 also applies.

Behaviours the check catches (canvas rule "Ordering or advising", easiest to over-block): "close your eyes", "take a break", "you should", "let's", "hang on", "don't push yourself", "it'll pass", "tell me first".

| ~~Reply count = K~~ | **Removed**: `rest_chat_endings` is no longer needed |
| AI-5 hit | S1 replaces his reply; the text is never used (NF6) |

Example ending from the NF6 wireframe: "I have to get back to the wiring." For the Canyon an ending would be of the kind "I have to get back to the canyon floor." (draft, not checked).

## 9. Latency and cost

One call per user message, ≤ 3 per pause. ≈ 500 input tokens (canvas blocks about 1,700 characters plus history) and ≤ 80 output tokens (estimate). Reply is shown only after checks, so **no streaming**; NF6 forbids a "typing…" indicator, so the user sees their own message and a short quiet wait (target ≤ 3 s, give up at 6 s and use the fallback). A retry doubles the wait.

## 11. Open questions

1. May his replies ask the user a question? Canvas candidates often did ("What was the fight about?"); one-way lines may not (R01). Chat could stay open-ended after the ending is returned, so a question invites a reply that will be blocked. **Recommendation (hypothesis)**: at most one, never in reply 3.
2. ~~K = 3 replies then an ending~~ **Decided: no limit.** The prototype's C1 note ("three replies at most") and NF6's "Kth line is a pre-written ending" now need updating.
3. "Are you an AI?": in character, an authored out-of-character line, or the About text only? Needs Yue and legal. No source decides it.
4. The canvas allows 1 to 3 sentences; C1 sample lines in NF6 v4 are 1 to 2. Test 1 to 2 (canvas help "Test 2" does exactly this).
5. Authored `rest_chat_fallback` (6) is still missing (D-AI-7). `rest_chat_endings` is no longer needed.
6. In production `now` is the entry state of the step; the canvas cases map slices s02, s04, s08, s11 to stages. The mapping to steps needs one line per stage.

## 12. Third Pause in one step: system warning (Yue's experiment, new)

**What is clear:** on the **third** Pause within the same step, the user gets a **system-voice** warning, authored, no model call: his step is going to fail; go back and start over.

**Draft wording (system voice, hypothesis, to be checked):** "This is the third pause on this step. If you stop again, his step will fail and you will start it over."  (No guilt words, no count of minutes, no his voice.)

**What the sources say that this touches (please decide, I did not):**
- FLOW and NF5 have a firm rule: no guilt, no streak, no "you missed", no punishment (R08, design.md). A failure consequence is a new kind of rule, so it needs its own wording review.
- Fate link says only the user's real completions advance the story. A "fail the step" outcome is the first case where the user's behaviour can **stop** it. Needs a definition: does the step restart at 0 minutes, does the story entry state stay, is anything logged for AI-7 (`rough` mode)?
- Is the failure real (a 4th Pause fails the step) or only a warning? "He is going to fail" is ambiguous; I wrote it as "if you stop again".
- Where it appears: on tapping Pause #3 (before the rest page), or on the rest page. I suggest on tap, with "Keep resting" and "Go back" choices, so the user decides.
- AI-3 on the third Pause: I suggest **no new stuck story** (authored obstacle only), to keep cost down and avoid dramatising the warning (hypothesis).
- Screen: needs a proposed ID, e.g. **R-WARN** (system card), plus the Back button on C1.

**Events (hypothesis):** `pause_n_in_step`, `pause_warning_shown`, `step_failed` (if real), no raw text.
