# Human steps checks

`npm run check:pr` (the CI job `pr-human-steps`) and `npm run check:deploy` (#189): the pull request must list its human steps, and a deployment is checked for 5xx, the signed-out redirect and the tables and row-level security of the migrations.

Path: `scripts/pr-checks.mjs` and `scripts/check-pr.mjs` (pull request body, migration file names, new environment variables), `scripts/deploy-check.mjs` and `scripts/check-deploy.mjs` (post-deploy check, Supabase Management API read). Both print plain sentences and never a value of a setting. The steps themselves: `docs/HUMAN_STEPS.md`. The database read is the Management API's "run a query" endpoint (`POST /v1/projects/{ref}/database/query` with `{"query": ...}` and a personal access token, answering a JSON array of rows; Supabase Management API reference: <https://supabase.com/docs/reference/api/introduction>). It is tested only against a local stand-in: the owner's first real run is its validation. On a Preview, `VERCEL_AUTOMATION_BYPASS_SECRET` is sent as `x-vercel-protection-bypass`.
