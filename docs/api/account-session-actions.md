# src/app/focus/actions.ts and src/app/rest/actions.ts

`src/app/focus/actions.ts` and `src/app/rest/actions.ts` (#257): server actions of the signed-in `/focus` and `/rest`. `loadAccountStepCards`, `loadAccountReturnLine`, `loadAccountPauseMessage` and `loadAccountRestReply` take the same requests as the `/try` actions (normalised by `src/lib/prototype/line-requests.ts`) and need a signed-in user. They go through `src/lib/progress/account-lines.ts`: there is no test data, so without a configured model every line is `{ status: "failed" }`; the rest reply still runs the safety gate first (`{ status: "crisis" }`). `recordFocusProgress(snapshot)` takes `{ sessionId, current, opened: boolean[], lines: { step, kind, seq, text, pauseNumber }[] }` (built by `snapshotOf` in `src/lib/progress/focus-session.ts`), applies it with `applyFocusSnapshot` and writes the Goal and session through `createSupabaseProgressStore`; it returns `false` when nothing was saved. Malformed lines are dropped; a stored line is never written again. All return `failed` or `false` without a signed-in user; none depends on `PROTOTYPE_ENABLED` (#278).

Since #114 the step cards, return line, pause message and rest reply actions, and `finishRunAction` (`src/app/end/actions.ts`), answer `{ status: "failed" }` with no model call for an account in the study condition (`storyIsOff`, `src/lib/research/condition.ts`), and also when the flag cannot be read.

Since #518 (REST-ROUND-10) `loadAccountRestReply` takes `sessionId` (added by the rest page from its Plan) and `pauseKey` (the Pause's own id, `rest.key`) and counts the rounds of that Pause on the account (`supabaseRestRounds`, `src/lib/progress/rest-rounds.ts`: `rest_round` and `record_rest_round` of `supabase/migrations/20261210000000_rest_rounds.sql`). Without both ids it answers `{ status: "failed" }` after the safety check. After round 10 it answers `{ status: "ended" }` with no model call; round 10's reply has `ended: true`. `loadAccountRestEnded({ sessionId, pauseKey })` answers `{ status: "ok", ended }` (or `failed`), so the rest page shows R1-C10 after a reload. Neither logs any text.
