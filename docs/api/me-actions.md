# src/app/me/actions.ts

`src/app/me/actions.ts` (#81, #71): `saveDisplayNameAction({ name })` returns `{ status: "ok", name }` (trimmed, 1 to 60 characters), `{ status: "crisis" }` (the server's safety check, `serverSafetyCheck()` at position `display_name`, flagged the name; nothing is saved; #392) or `{ status: "invalid" | "failed" }`; `setKeepClockRunningAction({ on })` (a boolean) returns `{ status: "ok" | "invalid" | "failed" }`. Both upsert the signed-in user's own `profiles` row (row-level security). `src/lib/me/me-view.ts`: `meView(progress)` gives `{ current, onHold, history }`; a history entry is a session with at least one done Step, its day is the first Done and its minutes are the Plan minutes of its done Steps. `src/lib/me/records.ts`: `sessionRecord(progress, id)` and `storyRecord(progress, id)` (only for a completed session). `src/lib/me/prefs.ts`: device settings under `waveparticle.prefs` with `readPrefs`, `writePrefs`, `applyPrefs` and `PREFS_SCRIPT`. `src/app/me/me-safety-gate.tsx`: `MeSafetyGate` wraps the Me page; `useShowCrisis()(onBack)` hides Me (still mounted) and shows S1 (`CrisisPage`) at `/me`; Back shows Me again and then calls `onBack` (the name field takes focus, empty). `src/lib/me/display-name-edit.ts` (#398): `displayNameReducer(state, event)` with `initialDisplayName(name)` is the name field's edit state: events `edit`, `type`, `save`, `cancel` and `answer { request, outcome }`. One Save at a time (a second `save` while `pending` changes nothing; the field is read-only and the button reads "Saving…" and is `aria-disabled`); `cancel` stops waiting for the pending request; a late answer (after Cancel, or for a Save a newer one replaced) is handled by its type (#400): `ok` means the server wrote the name, so `name` updates (and `draft` when not editing) and "Display name saved" is announced, unless a newer Save already set the name (`savedBy`); `crisis`, `invalid` and `failed` are ignored, so S1 never opens after Cancel; `edit`, `cancel` and every `save` clear `announce`; Save is `aria-disabled` (not `disabled`) while pending, so keyboard focus stays on it; an `invalid` or `failed` answer also raises `errorShown`, and the field takes focus if focus was lost anyway; a crisis answer empties the draft, keeps edit mode and raises `crisisShown` by one (the screen then shows S1 once).
