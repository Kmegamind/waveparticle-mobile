# AI feature tables and scripts (#436)

The database side of the AI feature pages (`supabase/migrations/20261130000000_ai_features.sql`, `docs/decisions/0032`): `public.ai_features` (one row per feature: `slug`, `position`, `title`, `prompt_keys text[]`, `purpose`, `pass_questions`, `approach` as JSON lists of `{ "text": string, "source": string | null, "draft": boolean }` where `[]` means "Not written yet", `status` one of `not_started`, `exploring`, `passed`, `frozen`, `sections_updated_at`, `sections_updated_by`), `public.ai_feature_status_history` (`feature_slug`, `from_status`, `to_status`, `note`, `changed_by`, `changed_at`) and `public.ai_feature_test_runs` (`feature_slug`, `prompt_key`, `kind` `fake_model` or `real`, `run_at`, `prompt_version`, `pass_count`, `fail_count`, `target_count`, `summary`, `report_path`, `imported_at`). Content editors read all three with `select`; nothing is written through the API except by these functions, both executable by `authenticated`:

- `public.save_ai_feature_sections(target_feature text, new_purpose jsonb, new_pass_questions jsonb, new_approach jsonb) returns void`: content editors (admin or writer); `42501` otherwise, `P0002` for an unknown feature, a check violation for a malformed list. Never changes the status.
- `public.set_ai_feature_status(target_feature text, new_status text, change_note text default null) returns void`: the admin role only (`42501` for a writer, no role or no session); `22023` for an unknown status, `P0002` for an unknown feature, an error when the status is already that value. Writes the history row in the same transaction.

Scripts (print SQL, connect to nothing, never call a model):

- `scripts/ai-features/seed.mjs [--dry-run]`: `parseFeaturePages(markdown)` and `readFeatureSeed(file?)` read section 3 of `docs/ai/AI_11_feature-pages.md` (each `- draft - owner to edit: <text> (source: <file>:<line>)` line becomes an item with `draft: true`); `seedSql(rows, { dryRun })` inserts each feature with status `exploring` only when its slug is missing. `featureSlug(name, keys)`, `quote(text)`, `STATUSES` and `START_STATUS` are exported too.
- `scripts/ai-features/import-runs.mjs [--dry-run] <offline-run folder>`: `readRunFolder(folder)` reads `results.json` (its `meta`), `targets.json` and `report.md` of a #42 run; `summaryStatuses(report)` reads the summary table; `testRunRows(run, { reportPath })` gives one row per feature and prompt key of each suite that ran (`SUITE_FEATURES`: `split` → `plan_split`, `rest` → `rest_reply`, `pause` → `pause_message`), kind `fake_model` unless `meta.mode` is `real`; `importSql(rows, { dryRun })` upserts on (`feature_slug`, `prompt_key`, `kind`, `run_at`). `reportPathOf(folder, root?)` stores the report path relative to the repository when it is inside it.

The e2e Supabase stand-in (`e2e/support/stub-supabase.mjs`) serves the three tables, both functions and `POST /__ai_features { reset?, testRuns? }`.
