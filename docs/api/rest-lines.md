# src/lib/prototype/rest-lines.ts

`src/lib/prototype/rest-lines.ts`: server-only `pauseMessageFor({ storyId?, pauseNumber, stepTitle, lastCard }, gateway)`, `restReplyFor({ storyId?, message, history, replyIndex }, gateway)` and `returnLineFor({ storyId?, trigger, awayMinutes }, gateway)`. Each uses the chosen story's inputs (#254). A missing `storyId` is chapter 8; an unknown one is `failed`, never another story. `src/lib/prototype/story-ids.ts` (client-safe) has `DEFAULT_STORY_ID` and `pickStory(stories, id)`, which every `/try` screen uses: the chosen story, otherwise chapter 8. The focus session's `planKey` includes the story, so one story's cards are never reused for another. Each returns `{ status: "ok", isTestData, text }` or `{ status: "failed" }`; any gateway result whose `source` is not `generated`, an empty line or an error is `failed` (NO-BACKUP, FAIL-SCREEN). `restReplyFor` runs `gateFreeText` first and returns `{ status: "crisis" }` without any call, drops crisis text from the history, sends at most the last six messages and `MAX_MESSAGE_CHARS` (1000) characters of a message, and tells the model to answer as a person of his own time (ERA-ANSWER). It passes the Story's words from after his date (`forbidTerms`) and every message the person typed in this chat (`userTexts`, crisis text left out), so the reply check fails a later word only when the person did not type it (#59, CHAT-USER-WORD). It also passes the facts from later in the Story (#60, CHAT-SPOILER-CHECK) from `laterStoryWords(content, storyId, { stepIndex, stepCount })` in `src/lib/prototype/rest-later-words.ts`: `laterFacts`, the spoiler words (`leaks`) of the stage 0 slices in the parts (stage 0 `steps`) the person has not reached, kept only when the entry has a capital letter or is a phrase of several words (single lower-case words are left out of this check only; `isChatLaterFact`), where the Step's reach follows `spreadCards` with one card per slice; and `laterWords`, the scene table's later words (`sceneTableOf`, #374). The rest page sends `stepIndex` (the current Step) and `stepCount` (the Plan's Steps), never a Step title; `normaliseRestRequest` keeps them only when they describe a Step of a Plan of at most 50 Steps, and without them only the first part counts as reached. The chat of a Pause ends at round 10 (REST-ROUND-10, #518; reverses R2): `restReplyFor` takes the reply's `round` and, at round 10, passes `lastRound: true`, so the gateway adds `REST_LAST_ROUND_INSTRUCTION` (`src/lib/model-gateway/rest-round.ts`) after the `rest_reply` prompt. `restReplyInRound(rounds, reply, afterTheEnd)` reads `rounds.answered()` (replies already shown in the Pause), answers `afterTheEnd()` after 10 with no model call, otherwise asks `reply(answered + 1)` and records the round only for an `ok` reply (so a retried failure keeps its round); round 10's reply carries `ended: true`; a count that cannot be read or written is `failed`. `afterTheLastRound(message, safety)` is `{ status: "crisis" }` for a crisis message, otherwise `{ status: "ended" }`. `roundsFromHistory(history)` is the test path's count (messages of the person answered by his next message); nothing is written. `pauseMessageFor` passes the story's scene table (`story.inputs.scene`, #64, #65) to `writeStuckStory` as `scene`, with `people` from all stories of the same Companion. `stuckFacts(pauseNumber)` carries the pause number, and from the third Pause the harder snag and his worry, never an instruction to the user (PAUSE-3). `returnLineFor` treats a line with any digit as `failed` until CLOCK-NUMBERS is decided. The calls pass the fields of both gateway shapes (`stepTitle` and `pauseNumber`; `trigger`). Without a gateway they return the chapter 8 test data: `pauseMessage`, `restReplies` in turn, `returnLine`.
