# src/lib/prototype/rest-lines.ts

`src/lib/prototype/rest-lines.ts`: server-only `pauseMessageFor({ storyId?, pauseNumber, stepTitle, lastCard }, gateway)`, `restReplyFor({ storyId?, message, history, replyIndex }, gateway)` and `returnLineFor({ storyId?, trigger, awayMinutes }, gateway)`. Each uses the chosen story's inputs (#254). A missing `storyId` is chapter 8; an unknown one is `failed`, never another story. `src/lib/prototype/story-ids.ts` (client-safe) has `DEFAULT_STORY_ID` and `pickStory(stories, id)`, which every `/try` screen uses: the chosen story, otherwise chapter 8. The focus session's `planKey` includes the story, so one story's cards are never reused for another. Each returns `{ status: "ok", isTestData, text }` or `{ status: "failed" }`; any gateway result whose `source` is not `generated`, an empty line or an error is `failed` (NO-BACKUP, FAIL-SCREEN). `restReplyFor` runs `gateFreeText` first and returns `{ status: "crisis" }` without any call, drops crisis text from the history, sends at most the last six messages and `MAX_MESSAGE_CHARS` (1000) characters of a message, and tells the model to answer as a person of his own time (ERA-ANSWER). `pauseMessageFor` passes the story's scene table (`story.inputs.scene`, #64, #65) to `writeStuckStory` as `scene`. `stuckFacts(pauseNumber)` carries the pause number, and from the third Pause the harder snag and his worry, never an instruction to the user (PAUSE-3). `returnLineFor` treats a line with any digit as `failed` until CLOCK-NUMBERS is decided. The calls pass the fields of both gateway shapes (`stepTitle` and `pauseNumber`; `trigger`). Without a gateway they return the chapter 8 test data: `pauseMessage`, `restReplies` in turn, `returnLine`.
