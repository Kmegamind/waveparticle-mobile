# API
There is no HTTP interface yet. The app is a Next.js application with one page (`src/app/page.tsx`).

Planned: Next.js route handlers for goal planning, story card generation, the rest conversation, safety checks and the return pop-up (see `docs/ai/` and `docs/CONTENT_MODEL.md`). When the first handler exists, document it in `docs/api/openapi.yaml`, generated from the real handler (methods, paths, status codes, bodies).

The public code interfaces today are:

- `src/lib/clock.ts`: `formatClock(totalSeconds)` returns `MM:SS` and never goes below `00:00`.
- `src/lib/story/start.ts`: `startStory(story, plan)` builds the brief for pressing Start. `plan` is a list of `{ minutes }`. The result carries the whole story, the step count taken from the plan, an instruction that the story is divided into that many steps and that the key slices are facts the writer must use, the facts for each step, and `mergedKeyMoments`. That list is empty when every key slice ended its own step. One step has `hasNextStepCards: false` and continues to the summary. No model is called.
- `src/lib/safety/keyword.ts`: `checkSafetyText(text)` returns `{ tier, flagged }` and does not return the text. Reused by the crisis page; do not copy its patterns.
- `src/lib/safety/crisis.ts`: `gateFreeText(text)` returns `{ action: "crisis-page", modelRequest: null }` when the keyword layer reports `crisis`, and `{ action: "continue" }` otherwise. The result never includes the text. `submitStepDraft` clears the draft on that path. `backToStep` returns an empty draft. Legal body text and the regional resource are placeholders until `docs/DECISIONS.md` or `docs/CONTENT_MODEL.md` states them.
- `src/lib/model-gateway/`: server-only `createModelGateway` and `createServerModelGateway`. The five calls are `splitPlan`, `writeStepCards`, `writeStuckStory`, `writeRestReply` and `writeReturnPopup`. There is no HTTP route for them yet. `writeStepCards` takes `StepCardsInput` = `{ minutes, facts, stepFacts?, stepNumber?, stepCount?, storyCards?, background?, mustUse?, forbidTerms?, earlierLines? }` and **no user-written text**: no Step title and no Goal (#216, US-AI-11). `facts` are who he is and where plus the Story facts of earlier Steps, and `stepFacts` the facts of this Step only (the prompt says "Already happened" and "New in this part", for CARD-NEW; an empty `stepFacts` tells the model that nothing new happens in this part, which is the case for Steps beyond the Story's facts); `stepNumber` and `stepCount` say where the Step sits in his Story; `storyCards` (1 to 5) is how many story cards follow the one opening card, and extra cards are dropped (T7; without it at most 5 cards are kept); `background` makes the first card the background card; `mustUse` are the key lines this Step must use (US-CON-2). Lengths follow CARD-LENGTH: a story card is 1 to 3 sentences and at most 45 words, the background card at most 70 words (`checks.ts`, kinds `step_card` and `background_card`). `writeStuckStory` takes `{ pauseNumber, facts, forbidTerms? }`: `pauseNumber` is the 1-based number of this Pause in the current Step (a value that is not a whole number of at least 1 is read as 1); from the third Pause the prompt asks for a much harder stuck situation in which he remembers the earlier setbacks and says he is worried he may fail, and it never tells the user what to do or asks the user to stop pausing (`docs/DECISIONS.md` F1, PAUSE-3). It takes no Step name, so no user text reaches this call (US-AI-11). `writeReturnPopup` takes `{ trigger, facts, awayMinutes, forbidTerms? }`: `trigger` is `"rest"` (Back from the rest conversation) or `"absence"` (back after being away, R1); the prompt differs by trigger and lets him say how the time felt in words, with no clock times or numbers (TIME-WORDS). Every line is checked by kind (`checks.ts`): step cards, the stuck story and the return pop-up allow no question and no "you"; a rest reply allows "you" and at most one question, and must still end with a full stop.

  **Results and failure (US-AI-8, decisions NO-BACKUP and FAIL-SCREEN).** Every call runs one pipeline: generate, parse, clean, check. An answer that fails is generated again with the failure reason added to the prompt (rule descriptions only, never user text), until it passes, `maxAttempts` (default 3) is used up, or the time limit `timeLimitMs` (default 12 000 ms, all attempts included; the real value is set by testing) runs out. A line is returned only after it passed. Success is `{ source: "generated", ... }` (`title` and `steps`, `cards`, or `text`). Failure is `{ source: "failed", reason }` with `reason` `"request"` (provider unreachable or error), `"timeout"` or `"checks"`; it carries no text, and the screen shows the calm failure message with a retry button and does not start the clock. The gateway holds no stored lines. `createServerModelGateway` takes the same `timeLimitMs` and `maxAttempts`. The log records `source` (`"generated"` or `"failed"`), `reason`, rule ids, latency and attempts.

  **Per-run list.** `writeStepCards`, `writeStuckStory` and `writeReturnPopup` take `earlierLines?: string[]`: the one-way lines already shown in this run, oldest first. The caller supplies them (for example from `session_lines`); the gateway keeps no state. A line is rejected (`repeat`) if it equals an earlier line ignoring case, punctuation and spacing; (`opening`) if its first three words equal those of one of the last four lines; (`similar`) if its content-word Jaccard similarity with any earlier line is 0.5 or more. Cards in one answer are also checked against the cards before them. `writeStuckStory` also takes `lastCard?: string`, the last card shown in the same Step; the stuck story may not reuse its nouns (`card_nouns`). Nouns are found by a heuristic: the one or two words after a determiner or possessive, plural "s" removed. The rest reply is a conversation turn and is not checked against the run list. `similarity`, `checkRunList` and `cardNouns` are exported from `run-list.ts`.
- `writeClosingLine({ facts, lastMoment, forbidTerms?, earlierLines? })` (#258, #41, END-TONE) returns `{ source: "generated", closingLine, carryLine }` or a failure. The model answers `{"closing_line","carry_line"}`. Both lines pass the existing one-way line checks (`CompanionKind` `closing_line` uses the default length: at most 3 sentences and 40 words) and the per-run list. The carry line is also checked against the closing line. The prompt says what happened to him that day and how he feels, never counts anything and never mentions pauses or the reader.
- `src/lib/summary/run.ts` (client-safe): `focusSecondsOf(session)` gives the real seconds on the device's clocks at Done, overtime included, or `null` before the last Done; `focusLabel(seconds)` gives "Under 1 min" or "N min".
- `src/lib/summary/finish-run.ts` (server):
  - `summaryOf(progress, sessionId)` gives `{ sessionId, storyTitle, goalTitle, steps, planMinutes, finished }` for the account's own Oppenheimer session, or `null`.
  - `finishAccountRun({ sessionId }, { userId, store, writer, gateway, nowIso })` returns `{ status: "ok", shown: { closingLine, carryLine, next } }` or `{ status: "signed-out" | "invalid" | "not-finished" | "failed" }`. The session must be `completed`.
  - When the session already has its closing line, that line comes back with no call.
  - Otherwise the model gets `closingInputFor(storyId, minutes, earlierLines)`: the story's inputs, the facts of the run and his shown cards in order, never Goal or Step text.
  - `nextStoryAfter` gives the next story only on a story's first completion.
- `src/lib/summary/run-writer.ts`: `claimClosingLine(sessionId, line)` sets `closing_line` only while it is empty (`claimed` or `taken`). A second tab that finds it taken waits for the stored lines. `insertClosingLine` writes the carried line as a `closing` row with a fixed id, ignoring duplicates. Nothing else on the account is written.
- `src/app/end/actions.ts`: server action `finishRunAction({ sessionId })` for `/end`. It answers `failed` when the test path is off, when the model is not configured, or on any error. Before calling it, `/end` sends the device's snapshot through `recordFocusProgress` (#257), so the account knows the session is complete.
- `src/app/_session/paths.ts`: `accountPathsFor(sessionId)` is `ACCOUNT_PATHS` with `end` set to `/end?session=<id>`.
- `src/lib/summary/life-path.ts`: `lifePath(progress, startId = chapter 1)` gives `{ periods: [{ name, rows }], currentId }`. Each row is `{ id, title, state, line }`, where `state` is `finished`, `memory` (a story before `startId`; its line is the story's goal sentence; none under M1, #272), `current` or `later`.
  - A finished row's `line` is the closing line of its first completed run.
  - The current row's `line` is the story's goal sentence.
  - A later row has no line.

  The current story is the first story with no completion; `storyForNewSession(progress)` is the story a new signed-in session plays (the current one, or the last). The periods are `PERIOD_DRAFTS` in `src/content/oppenheimer/periods.ts`, drafts until PERIOD-NAMES is approved.
- `src/app/continue-link.tsx` (#69 AC3): `continueHref(goal, sessionPagesEnabled)` gives `/focus?goal=<id>` for an `in_progress` Goal while the signed-in session pages exist (`PROTOTYPE_ENABLED`), otherwise `null`. `ContinueLink({ href })` renders it as a plain link (a full page load), so the focus page reads the device clock and opens the return pop-up after 5 minutes or more away or an open rest. Home and Goals use it; the Home Goal card (#86) can reuse it.
- `src/lib/prototype/config.ts`: `isPrototypeEnabled(env)` is true only when `PROTOTYPE_ENABLED` is `1`. `isTryPath(pathname)` and `tryPathIsHidden(pathname, enabled)` decide the 404 for `/try` in `src/proxy.ts`; `goalPathIsHidden` and `endPathIsHidden` do the same for `/goal` and `/end`.
- `src/lib/supabase/session.ts`: `isPublicPath(pathname, prototypeEnabled)` lists the paths a signed-out visitor may open: `/auth/*`, `/safety`, and `/try` only while the test path is on.
- `src/lib/prototype/store.ts`: browser-only test-path state `{ version, goal, steps, currentStep, storyId? }` (`storyId`: the chosen story, #254) with `loadPrototypeState`, `savePrototypeState` and `resetPrototypeState(storage)`. Broken or blocked storage gives the empty state and never throws.
- `src/lib/prototype/test-story.ts`: server-only `loadTestStory()` returns chapter 8 test data (`isTestData: true`): background card, four Steps with cards, pause message, rest replies, return line and closing line. Used only on `/try`.
- `src/lib/prototype/session.ts`: browser-only focus-page session for `/try/focus`, stored under its own key `waveparticle.prototype.session` (version 1). Pure functions that take the time as an argument: `syncSession(stored, plan, speed)` (a new session when the plan or speed changes), `setStepCards` (stores a Step's cards once; story cards beyond `maxStoryCards(minutes)` = 1 to 5, at least 5 minutes apart, are dropped; starts the current Step's clock), `remainingFor`, `visibleCards` (the opening card, then story card k at k·y/n of foreground time, the last at 00:00), `tick`, `completeStep` (Done; ignored during the 1.2 second hold `HOLD_MS`), `undoDone` and `canUndo` (`UNDO_MS` = 8 seconds), `pauseSession` and `resumeSession` (leaving or Pause freezes the clock), `loadSession`, `saveSession`, `clearSession`. `parseSpeed(value)` reads the test-only `?speed=` (a whole number from 1 to 600, otherwise 1): at speed s one minute of a Step lasts 60/s seconds.
- `src/lib/prototype/story-inputs.ts`: server-only inputs of the 26 Oppenheimer stories on the test path (#254), from `docs/demo/<story-id>.stage0.json` (AI-drafted, unreviewed, see each file's `_note`). `STORY_IDS` lists them in `stories.json` order. `generationInputs(id)` gives `{ who, place, goalShort, forbidTerms }`; the forbidden terms are the union of the file's list and `stories.json`. `storyProfile(id)` and `storyProfiles()` give `{ id, title, goalShort, who, opening }`, where `opening` is `whereNow.s1` followed by "What are you working on?". `validateStoryInputs(id, raw, story)` lists the problems in a file, each naming the story. Authored cards, example lines and people's lines in the files are never read.
- `src/lib/prototype/focus-cards.ts`: server-only `cardsForStep({ storyId?, index, planMinutes, earlierCards }, gateway)` (#254: the chosen story's facts and inputs; a missing `storyId` is chapter 8, and an unknown one makes `normaliseStepCardsRequest` return `null`) returns `{ status: "ok", isTestData, cards: { opening, story } }` or `{ status: "failed" }` (#43). With a gateway, the chapter 8 Story (`site-search` in `src/content/oppenheimer/stories.json`) is divided across the Plan's Steps with `startStory` (US-FMT-3): the call gets the facts of earlier Steps and, separately, this Step's facts (never a later Step's), this Step's must-use key lines, its place in the Story, `storyCards = maxStoryCards(minutes)`, `background` for Step 1, the story's forbidden terms, and `earlierCards` as the run's earlier lines (CARD-NEW). The first generated card is the opening card; any result whose `source` is not `generated`, an empty list, or an error is `failed` (FAIL-SCREEN). No Step title and no Goal text are sent (#216). `normaliseStepCardsRequest(raw)` checks the public request: 1 to 50 Plan Steps of 1 to 1440 minutes, an index inside the Plan, at most the last 60 earlier cards of at most 600 characters; every other field is dropped, and an unusable request is `null`. Without a gateway it returns chapter 8 test data: the background card opens Step 1, the "landing" card opens later Steps (a plan longer than four Steps reuses the fourth). `modelIsConfigured(env)` is true when `MODEL_API_KEY`, `MODEL_API_URL` and `MODEL_NAME` are all set.
- `src/app/try/focus/actions.ts`: server actions used by `/try/focus`: `loadStepCards(request)` (runs `normaliseStepCardsRequest` first; an unusable request is `failed`), and `loadReturnLine({ trigger, awayMinutes })` for the return pop-up (`trigger` is `rest` or `absence`; `awayMinutes` goes to the prompt only). Both return `failed` when the test path is off. Nothing about the request is logged.
- Rest and return in `src/lib/prototype/session.ts` (same key, still version 1; sessions stored before these fields load with the defaults): `startRest(session, now)` is Pause (freezes the clock, counts the Pause for the current Step in `pauses`, opens `rest = { pauseNumber, messages, draft }`), `pauseNumberFor`, `addFirstRestMessage` (his first message always goes first), `hasFirstRestMessage`, `addRestMessage` (no limit), `setRestDraft`, `backFromRest` (Back to step: rest ends, `returnPending = "rest"`), `leaveRest` (Home: the Step stays paused), `returnOnOpen(session, now)` (on opening the focus page with a frozen clock: an open rest counts as Back to step; away `AWAY_MS` = 5 minutes or more, divided by the test speed, sets `returnPending = "absence"`; otherwise the clock resumes), `setReturnLine` (stored once, never replaced), `startFromReturn` (Start: the pop-up closes and the clock continues from the frozen value). `pauseSession` records `pausedAtMs`, the first moment of the freeze.
- `src/lib/prototype/rest-lines.ts`: server-only `pauseMessageFor({ storyId?, pauseNumber, stepTitle, lastCard }, gateway)`, `restReplyFor({ storyId?, message, history, replyIndex }, gateway)` and `returnLineFor({ storyId?, trigger, awayMinutes }, gateway)`. Each uses the chosen story's inputs (#254). A missing `storyId` is chapter 8; an unknown one is `failed`, never another story. `src/lib/prototype/story-ids.ts` (client-safe) has `DEFAULT_STORY_ID` and `pickStory(stories, id)`, which every `/try` screen uses: the chosen story, otherwise chapter 8. The focus session's `planKey` includes the story, so one story's cards are never reused for another. Each returns `{ status: "ok", isTestData, text }` or `{ status: "failed" }`; any gateway result whose `source` is not `generated`, an empty line or an error is `failed` (NO-BACKUP, FAIL-SCREEN). `restReplyFor` runs `gateFreeText` first and returns `{ status: "crisis" }` without any call, drops crisis text from the history, sends at most the last six messages and `MAX_MESSAGE_CHARS` (1000) characters of a message, and tells the model to answer as a person of his own time (ERA-ANSWER). `stuckFacts(pauseNumber)` carries the pause number, and from the third Pause the harder snag and his worry, never an instruction to the user (PAUSE-3). `returnLineFor` treats a line with any digit as `failed` until CLOCK-NUMBERS is decided. The calls pass the fields of both gateway shapes (`stepTitle` and `pauseNumber`; `trigger`). Without a gateway they return the chapter 8 test data: `pauseMessage`, `restReplies` in turn, `returnLine`.
- `src/app/try/rest/actions.ts`: server actions `loadPauseMessage` and `loadRestReply` used by `/try/rest`. `loadRestReply` runs the safety gate again on the server. Both return `failed` when the test path is off. Not yet covered by a per-browser daily cap on model calls (to be added when the goal-dialogue cap is on `main`).
- `src/app/home-actions.ts` (#268): server action `setGoalStatusAction({ goalId, status, sessionId? })` with `status` `on_hold`, `done` or `in_progress` (Undo). It returns `{ status: "ok", previous, parkedSessionId? }` or `{ status: "failed" }`. Rules in `src/lib/home/goal-status.ts` (`setGoalStatus`): a signed-in user, a UUID of their own Goal (row-level security), and one of the three statuses; `on_hold` and `done` also park the Goal's newest `open` session as `on_hold`, and `in_progress` reopens exactly the session given as `sessionId` (the `parkedSessionId` of the change being undone) when it belongs to that Goal, is still `on_hold`, and the Goal has no open session. `src/lib/home/home-view.ts`: pure `homeView(progress)` returns `{ kind: "first" }`, `{ kind: "goal", card, companions, inProgress }` or `{ kind: "none", carriedLine, replay, companions }`.
- `src/app/me/actions.ts` (#81, #71): `saveDisplayNameAction({ name })` returns `{ status: "ok", name }` (trimmed, 1 to 60 characters) or `{ status: "invalid" | "failed" }`; `setKeepClockRunningAction({ on })` (a boolean) returns `{ status: "ok" | "invalid" | "failed" }`. Both upsert the signed-in user's own `profiles` row (row-level security). `src/lib/me/me-view.ts`: `meView(progress)` gives `{ current, onHold, history }`; a history entry is a session with at least one done Step, its day is the first Done and its minutes are the Plan minutes of its done Steps. `src/lib/me/records.ts`: `sessionRecord(progress, id)` and `storyRecord(progress, id)` (only for a completed session). `src/lib/me/prefs.ts`: device settings under `waveparticle.prefs` with `readPrefs`, `writePrefs`, `applyPrefs` and `PREFS_SCRIPT`.
- `src/app/focus/actions.ts` and `src/app/rest/actions.ts` (#257): server actions of the signed-in `/focus` and `/rest`. `loadAccountStepCards`, `loadAccountReturnLine`, `loadAccountPauseMessage` and `loadAccountRestReply` take the same requests as the `/try` actions (normalised by `src/lib/prototype/line-requests.ts`) and need a signed-in user. They go through `src/lib/progress/account-lines.ts`: there is no test data, so without a configured model every line is `{ status: "failed" }`; the rest reply still runs the safety gate first (`{ status: "crisis" }`). `recordFocusProgress(snapshot)` takes `{ sessionId, current, opened: boolean[], lines: { step, kind, seq, text, pauseNumber }[] }` (built by `snapshotOf` in `src/lib/progress/focus-session.ts`), applies it with `applyFocusSnapshot` and writes the Goal and session through `createSupabaseProgressStore`; it returns `false` when nothing was saved. Malformed lines are dropped; a stored line is never written again. All return `failed` or `false` when the test path is off.
- `src/app/try/goal/actions.ts`: server action `splitGoalAction({ goal, totalMinutes, splitFiner })` for the goal dialogue on `/try`. Returns `{ status: "plan", plan }`, `{ status: "failed" }` or `{ status: "crisis" }`. Answers `failed` when the test path is off. Rules in `docs/decisions/0012`.
- `src/lib/prototype/split-goal.ts`: `splitGoal(input, deps)`, the logic behind that action: safety gate first, then the model gateway (when `MODEL_API_KEY`, `MODEL_API_URL` and `MODEL_NAME` are set) or the test-data splitter. A non-`generated` result, an error or a plan that does not add up is `failed`. Never logs the goal text.
- `src/lib/prototype/test-splitter.ts`: `splitWithTestData(input)` (TEST DATA, 15-minute units). A goal containing `SPLIT_FAILURE_TOKEN` (`[fail-split]`) throws, for testing GD-F.
- `src/lib/prototype/cost-cap.ts`: `takeModelCall(cookie, today)` allows `MODEL_CALL_LIMIT` (20) real model calls per browser per day, counted in the httpOnly cookie `wp_try_model_calls`.
- `src/lib/prototype/goal-time.ts`: `parseTypedTime(text)` (5 to 300 minutes, rounded to 15, otherwise `null`), `findTimeInGoal(goal)` (GOAL-TIME), `formatMinutes(minutes)` and `TIME_HINT`.
- `src/lib/prototype/goal-lines.ts`: his draft dialogue lines (READ-STATUS: written), `pickReturningOpening(previous)`, `classifyGoalShape(goal)` and `reactionFor(shape)`.
- `src/lib/prototype/plan-edit.ts`: pure Plan edit rules (`commitTitle`, `setDescription`, `changeMinutes`, `addStep`, `removeStep`, `moveStep`, `canRemove`, `countLine`, `toSavedSteps`).
- `src/lib/prototype/opening-memory.ts`: `loadLastOpening` and `saveLastOpening(storage, index)` for the returning opening; never throws.
