# API
There is no HTTP interface yet. The app is a Next.js application with one page (`src/app/page.tsx`).

Planned: Next.js route handlers for goal planning, story card generation, the rest conversation, safety checks and the return pop-up (see `docs/ai/` and `docs/CONTENT_MODEL.md`). When the first handler exists, document it in `docs/api/openapi.yaml`, generated from the real handler (methods, paths, status codes, bodies).

The public code interfaces today are:

- `src/lib/clock.ts`: `formatClock(totalSeconds)` returns `MM:SS` and never goes below `00:00`.
- `src/lib/story/start.ts`: `startStory(story, plan)` builds the brief for pressing Start. `plan` is a list of `{ minutes }`. The result carries the whole story, the step count taken from the plan, an instruction that the story is divided into that many steps and that the key slices are facts the writer must use, the facts for each step, and `mergedKeyMoments`. That list is empty when every key slice ended its own step. One step has `hasNextStepCards: false` and continues to the summary. No model is called.
- `src/lib/safety/keyword.ts`: `checkSafetyText(text)` returns `{ tier, flagged }` and does not return the text. Reused by the crisis page; do not copy its patterns.
- `src/lib/safety/crisis.ts`: `gateFreeText(text)` returns `{ action: "crisis-page", modelRequest: null }` when the keyword layer reports `crisis`, and `{ action: "continue" }` otherwise. The result never includes the text. `submitStepDraft` clears the draft on that path. `backToStep` returns an empty draft. Legal body text and the regional resource are placeholders until `docs/DECISIONS.md` or `docs/CONTENT_MODEL.md` states them.
- `src/lib/model-gateway/`: server-only `createModelGateway` and `createServerModelGateway`. The five calls are `splitPlan`, `writeStepCards`, `writeStuckStory`, `writeRestReply` and `writeReturnPopup`. There is no HTTP route for them yet. `writeStuckStory` takes `{ pauseNumber, facts, forbidTerms? }`: `pauseNumber` is the 1-based number of this Pause in the current Step (a value that is not a whole number of at least 1 is read as 1); from the third Pause the prompt asks for a much harder stuck situation in which he remembers the earlier setbacks and says he is worried he may fail, and it never tells the user what to do or asks the user to stop pausing (`docs/DECISIONS.md` F1, PAUSE-3). It takes no Step name, so no user text reaches this call (US-AI-11). `writeReturnPopup` takes `{ trigger, facts, awayMinutes, forbidTerms? }`: `trigger` is `"rest"` (Back from the rest conversation) or `"absence"` (back after being away, R1); the prompt differs by trigger and lets him say how the time felt in words, with no clock times or numbers (TIME-WORDS). Every line is checked by kind (`checks.ts`): step cards, the stuck story and the return pop-up allow no question and no "you"; a rest reply allows "you" and at most one question, and must still end with a full stop.

  **Results and failure (US-AI-8, decisions NO-BACKUP and FAIL-SCREEN).** Every call runs one pipeline: generate, parse, clean, check. An answer that fails is generated again with the failure reason added to the prompt (rule descriptions only, never user text), until it passes, `maxAttempts` (default 3) is used up, or the time limit `timeLimitMs` (default 12 000 ms, all attempts included; the real value is set by testing) runs out. A line is returned only after it passed. Success is `{ source: "generated", ... }` (`title` and `steps`, `cards`, or `text`). Failure is `{ source: "failed", reason }` with `reason` `"request"` (provider unreachable or error), `"timeout"` or `"checks"`; it carries no text, and the screen shows the calm failure message with a retry button and does not start the clock. The gateway holds no stored lines. `createServerModelGateway` takes the same `timeLimitMs` and `maxAttempts`. The log records `source` (`"generated"` or `"failed"`), `reason`, rule ids, latency and attempts.

  **Per-run list.** `writeStepCards`, `writeStuckStory` and `writeReturnPopup` take `earlierLines?: string[]`: the one-way lines already shown in this run, oldest first. The caller supplies them (for example from `session_lines`); the gateway keeps no state. A line is rejected (`repeat`) if it equals an earlier line ignoring case, punctuation and spacing; (`opening`) if its first three words equal those of one of the last four lines; (`similar`) if its content-word Jaccard similarity with any earlier line is 0.5 or more. Cards in one answer are also checked against the cards before them. `writeStuckStory` also takes `lastCard?: string`, the last card shown in the same Step; the stuck story may not reuse its nouns (`card_nouns`). Nouns are found by a heuristic: the one or two words after a determiner or possessive, plural "s" removed. The rest reply is a conversation turn and is not checked against the run list. `similarity`, `checkRunList` and `cardNouns` are exported from `run-list.ts`.
