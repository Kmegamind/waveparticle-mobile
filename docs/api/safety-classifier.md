# src/lib/safety/ (classifier, check, alarm, server)

`src/lib/safety/check.ts`: `createSafetyCheck({ classifier, onEvent })` returns a `SafetyCheck`, `(text, { position, previous? }) => Promise<{ action: "crisis-page" | "continue", tier: "crisis" | "stress" | "none", layer: "keyword" | "classifier" | "keyword_alone" }>` (#117, US-SAF-4). The keyword layer runs first; a keyword crisis returns at once and the text reaches no model, the classifier included. Otherwise the classifier gets the text and the last two of `previous` (empty ones and keyword-flagged ones dropped). The higher tier wins (crisis > stress > none; the keyword layer's `low_mood` counts as `stress`). A classifier failure returns the keyword tier with `layer: "keyword_alone"` and emits `{ kind: "classifier_failed", reason, position, latencyMs }`; a crisis emits `{ kind: "crisis", layer, position, latencyMs, promptVersion }`. Events never carry the text. `keywordOnlySafetyCheck` is the check with no classifier, the default of every server function below. `position` is one of `goal_input`, `goal_title`, `goal_rename`, `plan_split`, `plan_edit`, `rest_chat`.

`src/lib/safety/classifier.ts`: `createSafetyClassifier({ provider, prompts, timeLimitMs? })` makes one call with the `safety_classifier` prompt (`docs/ai/prompts/safety_classifier.md`; placeholders `prev_1`, `prev_2`, `text`, each cut to 2,000 characters) and returns `{ ok: true, tier, promptVersion, latencyMs }` or `{ ok: false, reason: "timeout" | "request" | "parse" | "prompt", latencyMs }`. One attempt within `SAFETY_CLASSIFIER_TIME_LIMIT_MS` (1,500 ms), the prompt read included; at the limit the request is aborted. `parseClassifierAnswer(raw)` accepts only one JSON object with exactly one key `tier` (`crisis`, `stress`, `none`, or `unsure`, which is read as `crisis`), with an optional code fence; anything else is null (a failure).

`src/lib/safety/alarm.ts`: `createSafetyAlarm({ webhookUrl, fetchImpl?, counter?, today?, log? }).classifierFailed(reason)` posts `{ text, content }` (the same sentence: the UTC day, the day's failure count so far, the reason) to `webhookUrl` when `counter(day)` says this is the day's first alarm. Without `webhookUrl` it logs `safety_alarm_not_configured` and returns. A failing counter falls back to this instance's own once-a-day rule; a failing webhook logs `safety_alarm_failed`. It never throws.

`src/lib/safety/server.ts` (server only): `serverSafetyCheck()` is the check every server action passes on, built once per instance from `process.env`. `safetyClassifierSettings(env)` reads `SAFETY_MODEL_API_KEY`, `SAFETY_MODEL_API_URL` and `SAFETY_MODEL_NAME`, each falling back to `MODEL_API_KEY`, `MODEL_API_URL` and `MODEL_NAME`; null when one is missing (then no classifier and no alarm). Failures log `safety_classifier_failed` (level error) and crises `safety_crisis` (level warn), feature `safety`, with `reason` or `layer`, `position`, `promptVersion` and `durationMs`, never text; the alarm runs after the response (`after`). The day counter is `public.record_safety_classifier_failure(reader_token)` (`supabase/migrations/20261127000000_safety_alarm_days.sql`, `PROMPTS_READ_TOKEN`), which returns `{ failures, send_alarm }` and is true for the first call of a UTC day only.

Callers (each takes an optional `safety: SafetyCheck`, keyword only if omitted): `restReplyFor(source, request, gateway, safety?)` (position `rest_chat`, previous = the person's earlier messages in the request), `accountRestReply(content, raw, gateway, safety?)` (one check; with no gateway only the keyword layer), `takeTurn` (`TurnDeps.safety`, the goal line, `goal_input`), `splitGoal` (`SplitDeps.safety`, `plan_split`), `startGoal` (`deps.safety`: the goal, the title and the Plan's Step titles and descriptions as one text, three checks side by side) and `renameGoal` (`deps.safety`, `goal_rename`).
