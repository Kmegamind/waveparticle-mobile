# src/lib/safety/ (classifier, check, alarm, server)

`src/lib/safety/check.ts`: `createSafetyCheck({ classifier, onEvent, now? })` returns a `SafetyCheck`, `(text, { position, previous? }) => Promise<{ action: "crisis-page" | "continue", tier: "crisis" | "stress" | "none", layer: "keyword" | "classifier" | "keyword_alone" }>` (#117, US-SAF-4). The keyword layer runs first; a keyword crisis returns at once and the text reaches no model, the classifier included. Otherwise the classifier gets the text and the last two of `previous` (empty ones and keyword-flagged ones dropped). The higher tier wins (crisis > stress > none; the keyword layer's `low_mood` counts as `stress`). A classifier failure returns the keyword tier with `layer: "keyword_alone"` and `classifierFailed: true` (absent when there is no classifier) and emits `{ kind: "classifier_failed", reason, ...fields }` (its `classifierPromptVersion` is the prompt read before the failure, when there was one); a crisis emits `{ kind: "crisis", ...fields }`. `fields` (`SafetyEventFields`, #119 US-SAF-6) are exactly `at` (ISO time, UTC), `position`, `tier`, `lang` (`SAFETY_CHECK_LANGUAGE`, `"en"`), `keywordListVersion` (`KEYWORD_LIST_VERSION` in `keyword.ts`), `classifierPromptVersion` (the `safety_classifier` prompt version that answered, or null), `layer` and `latencyMs` (the whole check). Events never carry the text, its length or a hash of it. `keywordOnlySafetyCheck` is the check with no classifier, the default of every server function below. `position` is one of `goal_input`, `goal_title`, `goal_rename`, `plan_split`, `plan_edit`, `rest_chat`, `display_name`.

`src/lib/safety/classifier.ts`: `createSafetyClassifier({ provider, prompts, timeLimitMs? })` makes one call with the `safety_classifier` prompt (`docs/ai/prompts/safety_classifier.md`; placeholders `prev_1`, `prev_2`, `text`, each cut to 2,000 characters, with `<<<` and `>>>` in the person's text turned into `‹‹‹` and `›››` so a message cannot close its own block) and returns `{ ok: true, tier, promptVersion, latencyMs }` or `{ ok: false, reason: "timeout" | "request" | "parse" | "prompt", latencyMs }`. One attempt within `SAFETY_CLASSIFIER_TIME_LIMIT_MS` (1,500 ms), the prompt read included; at the limit the request is aborted. `parseClassifierAnswer(raw)` accepts only one JSON object with exactly one key `tier` (`crisis`, `stress`, `none`, or `unsure`, which is read as `crisis`), with an optional code fence; anything else is null (a failure).

`src/lib/safety/alarm.ts`: `createSafetyAlarm({ webhookUrl, fetchImpl?, counter?, today?, now?, log? }).classifierFailed(reason)` posts `{ text, content }` (the same sentence: "the first safety classifier failure today", the UTC day and time, the reason, and that later failures today are only in the server log) to `webhookUrl` when `counter(day)` says this is the day's first alarm. Without `webhookUrl` it logs `safety_alarm_not_configured` and returns. A failing counter falls back to this instance's own once-a-day rule; a failing webhook logs `safety_alarm_failed`. It never throws.

`src/lib/safety/server.ts` (server only): `serverSafetyCheck()` is the check every server action passes on, built once per instance from `process.env`. `safetyClassifierSettings(env)` reads `SAFETY_MODEL_API_KEY`, `SAFETY_MODEL_API_URL` and `SAFETY_MODEL_NAME`, each falling back to `MODEL_API_KEY`, `MODEL_API_URL` and `MODEL_NAME`; null when one is missing (then no classifier and no alarm, and the server logs `safety_classifier_off` once). Failures log `safety_classifier_failed` (level error, plus `reason`) and crises `safety_crisis` (level warn), feature `safety`, with exactly the event's fields (`safetyLogFields(event)`, #119), never text; the alarm runs after the response (`after`). The day counter is `public.record_safety_classifier_failure(reader_token)` (`supabase/migrations/20261127000000_safety_alarm_days.sql`, `PROMPTS_READ_TOKEN`), which returns `{ failures, send_alarm }` and is true for the first call of a UTC day only.

Callers (each takes an optional `safety: SafetyCheck`, keyword only if omitted): `restReplyFor(source, request, gateway, safety?)` (position `rest_chat`, previous = the person's earlier messages in the request; each earlier message of the person not directly followed by his reply is checked again at the same time, with the person's messages before it as `previous`, at most `MAX_UNANSWERED_RECHECKS` (3), and left out of the reply model's input when flagged or when `classifierFailed`; older unanswered ones are left out unchecked), `accountRestReply(content, raw, gateway, safety?)` (one check; with no gateway only the keyword layer), `takeTurn` (`TurnDeps.safety`, the goal line, `goal_input`), `splitGoal` (`SplitDeps.safety`, `plan_split`), `startGoal` (`deps.safety`: the goal, the title and `planPieces(steps)`, whole Steps joined up to 2,000 characters, all checks side by side; 3 calls for a usual Plan, at most 52) `renameGoal` (`deps.safety`, `goal_rename`) and `saveDisplayName` (`deps.safety`, `display_name`, no `previous`; after the length check, before the write; #392, SAFETY-FIELDS-NAME). The display name is the only account setting sent to the model provider, and only to the classifier.

`src/lib/safety/next-action.ts`, `src/lib/safety/next-action-request.ts` and `src/app/safety/next-action/route.ts` (#119): S1 (`crisis-page.tsx`) sends one request to `POST /safety/next-action` with `{ action, screen }`, as a `keepalive` fetch with no referrer and no cookies (`NEXT_ACTION_REQUEST`; `navigator.sendBeacon` is not used because it cannot drop either). `action` is the first of `get_support`, `second_contact`, `directory`, `choose_country`, `back`, or `left` (page hidden first); `screen` is the first part of the page address from a fixed list (`s1Screen`), else `other`. The route refuses with 403 a request whose `Sec-Fetch-Site` is not `same-origin`, or, from a browser that sends no `Sec-Fetch-Site`, whose `Origin` host is not the request's `Host` (`isSameOrigin`), a body over 200 bytes with 413 (counted in bytes while reading, whatever `content-length` says), and anything but exactly those two keys from the lists with 400; nothing is logged for a refused request. It answers 204 and logs `safety_next_action` with `at`, `action`, `screen` and `lang`. There is no rate limit. The JSON line carries no id that joins it to the `safety_crisis` line, but the hosting platform records each request's address, time, IP address and browser, so the two could be matched by time and IP address. Public path, named in `isPublicPath`; the handler reads no cookie and the page sends none. The whole site sends `Referrer-Policy: strict-origin-when-cross-origin` (`next.config.ts`).

`src/lib/safety/log-policy.ts` (#119 AC3, pending the legal review #121): `SAFETY_LOG_RETENTION_DAYS` (90), `SAFETY_LOG_READERS` (`vercel-project-members`), `SAFETY_LOG_POLICY_PENDING_LEGAL` (true). See `docs/deploy.md`, "Safety log".
